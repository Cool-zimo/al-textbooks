【ROADMAP 写得很好，但第四节「硬性规则」有 2 条已经过时了】

你写 ROADMAP 时按的还是旧情况，这两条我在上一轮已经改掉了：

  规则 1：「quiz 里不能出现 input()，int(input()) 会当场崩」
    → 已失效。stdin 字段已经实现：
        ```quiz
        type: code
        stdin: |
          18
        tests:
        - assert "2007" in __out
        ```
      题目声明 stdin 后，判分会按行喂给 input()。
      不声明则维持空串（向后兼容，你现有题目不受影响）。
      **第 3 章的题现在可以真正考 input 了。**

  规则 2：「引用块里不能放代码围栏，> ```python 会渲染成纯文本」
    → 已修复。真实原因比你判断的更严重：问题不在 markdown.js 的 ^> 分支，
      而在 renderLesson 的切分阶段 —— 那个正则不区分围栏是否在引用块内，
      把 `> ```python` 当普通围栏切走了，切出来的代码**带着 "> " 前缀**：

        block: lang=python, code='> print("hi")\n> '    ← 非法 Python

      所以它渲染出的不是"文本"，而是一个**跑不了的代码块**，比纯文本更糟。
      已修两处（renderLesson 跳过引用块内围栏 + fallbackRender 新增块内围栏分支），
      顺带修了一个隐藏 bug：fallbackRender 开头有 esc() 把 > 转成 &gt;，
      导致 ^> 分支**在降级路径下从来没生效过**。现在两处正则都认 > 和 &gt;。

  → 建议把 ROADMAP 第四节这两条改掉，否则会误导后面写教材的人。

【校验器我升级了：能识别「故意错误」】

（如 `if score >= 60` 少冒号、`print` 忘缩进、`if score = 60` 用等号）——

"修好这段代码""找出错误"，就判为故意错误并豁免。修完之后：

  12 文件 / 46 题 / 28 道 code 题 / 22 处故意错误豁免 → **0 问题**

覆盖了新手 if 报错的八成。后面章节可以继续用这个手法。
