# AnyLearn 教材仓库 · al-textbooks

通学万义（AnyLearn）的**教材内容仓库**。

与主站 `Cool-zimo/al` 分离存放，目的是**规避协作时的版本冲突**：
教材作者在独立仓库里写，写好后由协作者一次性克隆进主站。

## 目录结构

```
content/
  zh/books/<book-id>/lessons/NN.md     # 中文课文
  zh/books/<book-id>/toc.json          # 中文目录（章节 + 章测）
  zh/books.json                        # 书元数据（ready 决定是否在书城显示）
  en/...                               # 英文，与 zh 逐文件对齐
```

文件名必须与 `toc.json` 里的 `id` 一致（`01` → `01.md`，`test-01` → `test-01.md`）。

## 教材写作标准

从现有课文归纳出的硬约束，写新课请遵守：

**结构**：`# 标题` → 引子 → 若干 `## 讲解节` → `## 小测验`（1 题）→ `---` → `## 本节测验`（2 题，标 `exam: true`）。

**讲法**：不假设任何编程概念，每个知识点从「它解决什么问题」讲起。生活化比喻 → 表格对比 → 可运行示例 → 常见翻车现场。

**quiz 引擎的真实能力**（写题前必读，否则题会判不了分）：

| 支持 | 不支持 |
|---|---|
| `assert ... in __out`（验证打印了什么） | `__src` —— 引擎不暴露源码，写进去必失败 |
| 用户代码里定义的变量（同一命名空间） | 判分时 `input()` 返回**空字符串** |
| `choice` / `fill` / `code` / `project` 四种题型 | starter 里写 `int(input())` 会当场 `ValueError` |

所以：**需要「用户输入」的题，starter 里用预置变量模拟**（如 `age_text = "18"`），
不要依赖 `input()` 的返回值做判分。

**渲染限制**：`> ```python` 这种「引用块里嵌代码围栏」**不会被渲染**
（`markdown.js` 的引用分支没有代码块处理），会原样显示成文本。代码块要独立成段。

## 质量校验

写完跑一遍，能挡住绝大部分低级错误：

- 所有 `python` 代码块能通过 `ast.parse`
- 无 `__src` 残留
- `choice` 题的 `answer` 索引不越界
- `code` 题的 starter 不含 `int(input())` 之类判分会崩的写法
- **每道 code 题写出「参考解」真跑一遍，确认 tests 能通过**（最重要的一条）
