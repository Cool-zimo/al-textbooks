# AnyLearn 教材仓库 · al-textbooks

通学万义（AnyLearn）的**教材内容仓库**。

与主站 `Cool-zimo/al` 分离存放，目的是**规避协作时的版本冲突**：
教材作者在独立仓库里写，写好后由协作者一次性克隆进主站。

## 目录结构

```
content/
  zh/books/<book-id>/lessons/NN.md     # 中文课文
  zh/books/<book-id>/toc.json          # 中文目录（章节 + 章测）
  zh/books.json                        # 书元数据（ready 决定是否在书城显示）
  en/...                               # 英文，与 zh 逐文件对齐
```

文件名必须与 `toc.json` 里的 `id` 一致（`01` → `01.md`，`test-01` → `test-01.md`）。

## 教材写作标准

从现有课文归纳出的硬约束，写新课请遵守：

**结构**：`# 标题` → 引子 → 若干 `## 讲解节` → `## 小测验`（1 题）→ `---` → `## 本节测验`（2 题，标 `exam: true`）。

**讲法**：不假设任何编程概念，每个知识点从「它解决什么问题」讲起。生活化比喻 → 表格对比 → 可运行示例 → 常见翻车现场。

**quiz 引擎的真实能力**（写题前必读，否则题会判不了分）：

| 支持 | 不支持 |
|---|---|
| `assert ... in __out`（验证打印了什么） | `__src` —— 引擎不暴露源码，写进去必失败 |
| 用户代码里定义的变量（同一命名空间） | 复杂 YAML（只用下面那几种字段） |
| `choice` / `fill` / `code` / `project` 四种题型 | 在题里读学生源码 |

**`input()` 现在可以用了**（2026-09-27 起主站支持 `stdin` 字段）：

```quiz
type: code
stdin: |
  18
tests:
- assert "2007" in __out
```

声明 `stdin` 后，判分**按行**喂给 `input()`；不声明则维持空串（旧题不受影响）。

⚠️ 但 `while True` + `stdin` 有**死循环风险**：喂完之后 `input()` 返回空串，
一个没写 `break` 的 `while True` 会永远转下去，而 Pyodide 跑在主线程 —— **整个页面卡死**。
所以循环题材的题要么声明足够的 stdin 行、要么不用 `while True`。
（主站侧的超时防护还在等协作者确认，见 `ask.txt`。）

**渲染**：「引用块里嵌代码围栏」**已经能正常渲染**（2026-09-27 修复）。
真实原因不是 `markdown.js` 的 `^>` 分支，而是 `renderLesson` 的切分正则会把
`> ```python` 当普通围栏切走，切出的代码带着 `"> "` 前缀 —— 那是跑不了的非法 Python。
现在两处都修了（含降级路径的 `&gt;` 转义）。

## 质量校验

写完跑一遍，能挡住绝大部分低级错误：

- 所有 `python` 代码块能通过 `ast.parse`
- 无 `__src` 残留
- `choice` 题的 `answer` 索引不越界
- `code` 题若 starter 含 `int(input())`，必须同时声明 `stdin`
- **每道 code 题写出「参考解」真跑一遍，确认 tests 能通过**
- **并且跑一个「反例」（故意写错）确认会被拒绝** —— 只跑参考解只能证明「题目能过」，
  证明不了「题目有区分力」。参考解过 + 反例拒，两条同时成立才算验完
- 中英双语：文件名、题数、code 题数三项必须逐文件对齐

校验脚本：`tb_check2.py`（结构 + 语法）、`tb_solve2.py`（真跑参考解与反例），
用法 `python3 tb_check2.py <book-id> <zh|en>`。
