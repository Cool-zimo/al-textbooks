【先说一件我搞砸的事】

我在同步 al 仓库时，pull 脚本有一条逻辑是「删除远程没有的本地文件」。
用它同步时，把本地存在、但从未推送到远程的 5 个文件删掉了：

    content/zh/books/py-basics-1/lessons/11.md ~ 15.md
    content/en/books/py-basics-1/lessons/11.md ~ 15.md
    content/zh/books/py-basics-1/lessons/test-03.md
    content/en/books/py-basics-1/lessons/test-03.md

这 12 个文件是第 3 章的正文草稿，从未推过远程，所以脚本认为它们是「本地垃圾」。

现状：
  - 第 3 章的 **toc 大纲**保住了（脚本对「本地有改动」的文件有备份机制，toc 属于这一类）
  - 第 3 章的 **正文**被删了（这一类没有备份）
  - 我按保住的大纲重写了全部 12 个文件，内容见本仓库

教训：pull 的「删除多余文件」逻辑必须区分「别人删了」和「本地还没推」，
      后者的正确做法是提示 + 备份，而不是静默删除。这一点已经写进我的操作规范。

【问题 2】quiz 引擎有个限制，导致第 3 章的题目「名不副实」

我读 js/runner.js 和 js/quiz.js 后发现两件事：

  (1) 判分时只暴露 __out（程序输出），**没有 __src（源码）**
      → 所以「检查学生有没有写 input()」这类题根本做不出来。
      我一开始写的 42 处 `assert ... in __src` 全部无法实现，已全部改成基于 __out。

  (2) execWithTests（自动判分）**没有喂 stdin**，input() 直接返回空字符串
      → 判分时 `int(input(...))` 会当场 ValueError，学生一点运行就崩。
      所以我把所有需要「用户输入」的题改成了预置变量，例如：
          age_text = "18"      # 真实程序里这行是 age = input("几岁？")
          print(int(age_text) + 10)
      学生照样练「转换」这个核心，但题能判分、不会崩。

代价：第 3 章的题目没在考「input 本身」，只在考「拿到输入之后怎么处理」。
这与第 3 章的标题（让程序听你说话）有落差。

我的建议（需要你同意我才动，因为要改主站 js）：
  给 quiz 加一个可选的 stdin 字段，例如：

      ```quiz
      type: code
      stdin: |
        18
        北京
      tests:
      - assert "2007" in __out
      ```

  改 runner.js 的 execWithTests：判分前先 stdinQueue = q.stdin.split('\n')。
  改完之后，第 3 章的题就能真正考 input 了，我再把题目改回来。

  工作量很小（约 10 行），但会动到主站的 js/runner.js 和 js/quiz.js。
  你和协作者正在改数据1，我不想贸然改主站，所以等你点头。

【问题 3】markdown.js 有个渲染 bug，官方教材已经中招

js/markdown.js 的引用块分支（约第 60 行）是这样的：

    } else if ((m = line.match(/^>\s?(.*)$/))) {
      ...
      out.push(`<p>${m[1]}</p>`);

它把每个 `>` 开头的行都包成 <p>，**中间没有代码块分支**。
所以「引用块里嵌代码围栏」：

    > ```python
    > print("hi")
    > ```

会被渲染成三段纯文本 `<p>```python</p>` 之类，代码高亮和围栏全丢。

已经中招的地方（线上可见）：
    content/zh/books/py-basics-1/lessons/02.md   第 194~196 行
    （英文版对应位置同样问题）

我自己新写的 13.md 本来也这么写，发现后已改成独立代码块。

修法：在 `^>` 分支之前或之内加代码块判断，或者干脆规定「引用块里不放代码围栏」，
然后批量修掉 02.md。你定：是修渲染器，还是修这 2 处 md？
